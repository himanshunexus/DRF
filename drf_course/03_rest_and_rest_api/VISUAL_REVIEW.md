## What was visible

The sampled slides use students as the resource, distinguish a collection URL from a student-specific URL, and map GET, POST, PUT, PATCH and DELETE to those endpoints.

## Vocabulary to recognize

`REST Web API`, `Students API Resource`, `Request`, `Response`, `GET`, `POST`, `PUT`, `PATCH`, `DELETE`.

## How this project follows the lesson

Keep student-resource names and add the collection/detail method table to the lesson notes. Explain that the introductory project demonstrates GET and later projects implement all methods.

## Try it in this project

Collection: GET lists students, POST creates. Detail: GET reads one, PUT replaces required writable fields, PATCH changes supplied fields, DELETE removes. This introductory project demonstrates GET; lessons 9–17 supply writable examples.
